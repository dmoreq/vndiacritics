# Corpus v2: register-balanced mixture (data-v2b)

**Date**: 2026-10-25
**Base**: commit `ff3310a`
**Pipeline**: `scripts/fetch_corpus_v2.sh` (fetch → extract → per-source build → merge)

## 1. Composition

v2b = the 2017 news corpus (v1, 400M tokens) **plus** three license-clean,
cased sources. The v1 corpus stays a mixture component: v2-only experiments
below show why — v1 carries news-register mass that no new source replicates.

| Source | Tokens extracted | Register | License |
|---|---:|---|---|
| v1 2017 news (upstream, pinned) | ~400M | news | unlicensed, fetched not committed |
| Wikipedia vi `20261001`, every 2nd article | ~200M | encyclopedic | CC BY-SA 3.0 |
| OpenSubtitles v2024 en-vi, Vietnamese side (credit-filtered, 80.8% of 37.0M lines) | ~250M | conversational | ODC-BY |
| vietnamese-legal-documents `content.parquet` (170,824 docs) | ~245M | official/legal | CC BY 4.0 |

Merged tables: 2.97M unigrams, **25.2M bigrams** (v1: 216k / 5.5M). Trie 240MB;
model load 8.2s incl. case tables (v1: 0.29s); throughput ~1,140 sent/s
(v1: ~1,850).

## 2. Measured gates (the pre-registered decision rule)

`bench/baseline.py --data vndiacritics/data-v2b --tag v2b-full`,
`bench/register_accuracy.py --data vndiacritics/data-v2b`:

| Register | v1 | v2b (K=1000, shipped config) | Delta |
|---|---:|---:|---:|
| in-domain (2017 news, 8,995 tokens) | **96.05%** | 95.11% | −0.94 |
| out-domain overall (883 tokens) | 95.58% | **96.38%** | +0.80 |
| news / long-form | 98.54% | **99.03%** | +0.49 |
| official documents | 95.51% | 95.51% | 0 |
| contracts / business | 95.12% | **96.10%** | +0.98 |
| everyday / conversational | 89.89% | **92.55%** | +2.66 |

Recorded from `bench/register_results.json` and `bench/baseline_results_v2b-final.json`
after pinning K=1000 via model.json. An earlier auto-K run measured 95.08 / 96.15 /
92.02 / 95.61 — the pre-registered gates pass in both configurations.

| Gate | Threshold | v2b | Verdict |
|---|---|---:|---|
| in-domain (CI gate) | >= 95.0% | 95.11% | PASS |
| out-domain | >= 95.24% | 96.38% | PASS |
| conversational | >= 91% | 92.55% | PASS |
| **default switch** | **in-domain >= 96.0%** | **95.11%** | **FAIL** |

**Decision (pre-registered in the upgrade plan)**: v1 stays the default
corpus. `data-v2b` ships as the register-balanced alternative
(`Model.load("vndiacritics/data-v2b")`, CLI `--data vndiacritics/data-v2b`) and
as the case-statistics source for `case="correct"`, which REQUIRES it.

## 3. What did not work (measured, so nobody retries)

| Variant | in-domain | out-domain | conversational | Verdict |
|---|---:|---:|---:|---|
| wiki(1-in-7) + full subs + legal, no v1 | 91.26% | 96.04% | 91.49% | in-domain collapse |
| wiki(1-in-2) + full subs + legal, no v1 | 91.17% | 95.47% | 89.36% | worse: subs at 1/3 lost conversational AND kept the collapse |
| v2b with `bigram_skip_below=0` | 91.58% | 95.47% | — | skip threshold is not the cause |
| v2b with beam 16/32 | 91.31/91.28% | — | — | beam is not the cause |
| K sweep 0..10000 on v2b | 94.99–95.13% | 96.15–96.38% | — | K is not the cause |

The no-v1 collapse (~-4.8 in-domain) is structural: the 2017 news eval needs
news-domain statistics, and encyclopedic + legal + subtitle statistics cannot
substitute. Adding v1 as the fourth source recovers 3.9 of those points while
keeping all new-register gains.

## 4. K re-measurement (per-corpus smoothing)

`bigram_conf_k` sweep on v2b: K=1000 maximizes both golds (95.11% / 96.38%).
The auto default (`t1 * 2.5e-6` = 2,824 on this corpus) scores 95.13% / 96.15%.
`Model.load` now reads a corpus-local `model.json`
(`{"bigram_conf_k": 1000}`), so a corpus carries its own measured K;
re-run `bench/ab_confidence.py` after any mixture change.

## 5. Reproduce

```bash
./scripts/fetch_corpus_v2.sh          # ~3GB downloads, ~40 min, fully cached
.venv/bin/python bench/baseline.py --data vndiacritics/data-v2b --tag v2b-full
.venv/bin/python bench/register_accuracy.py --data vndiacritics/data-v2b
```

Downloads land in gitignored `.tmp/corpus_v2/`; sources and licenses are in
[CORPORA.md](../../CORPORA.md); per-source table stats are printed by the
fetch script.
